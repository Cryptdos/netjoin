# NetJoin v0.9 – arrange the Sites list

Branch: `v0.9` (built on `v0.8`). Status: first build for testing.

## What it does

Items in the Sites list can be dragged to reorder them, and dropped onto a site or area to nest them inside it. Example: a network was added straight under a site; later an area is added – drag the network onto the area and it moves inside.

## Rules

| Moving | Can go |
|---|---|
| Site | Before / after another site (top level only) |
| Area | Before / after anything in the **same site**, or inside the site or another area of it |
| Network | Before / after anything in the **same site**, or inside the site or an area of it |

- **Nothing moves between sites.** Drop targets in other sites don't light up; the server refuses it too.
- Nothing goes inside itself or inside something it contains.
- Nothing goes inside a network.

## How to drag

| Where you drop on a row | Result |
|---|---|
| Top edge | Before it (blue line above) |
| Bottom edge | After it (blue line below) |
| Middle of a site or area | Inside it, at the end (row outlined) |
| Anywhere on a site row (moving an area / network) | Inside that site |

- Hovering over a closed site or area for about half a second opens it, so you can go deeper.
- Dragging is off while the Sites search box has text in it.
- The order you set is saved. New items go to the end of their list.

## Without a mouse

**Edit** on an area or network has an **Inside** picker listing its site and that site's areas (not itself or anything inside it). Change it and Save to move.

## Things that follow a move

- Breadcrumbs, the device roll-ups on site / area pages and History paths follow the new place.
- A network's gateway / DNS can come from the area or site above it, so moving it can change what it inherits. If the laptop is on that network, the same rules as editing apply: additions go on straight away, anything that changes or removes a gateway / DNS in use asks first.
- The Activity log records each move ("Moved network 'FCU' to 50 Berkeley Street › Level 2").

## Back end

- `POST /api/nodes/{id}/move {parent_id, index}` → `store.move_node()`; returns the node plus `live` (as for edits).
- Uses the existing `nodes.sort` column; the first move in a list numbers the whole list so the order is explicit from then on.

## Tested (demo mode)

Network into an area, reorder inside an area, area before area, sites reordered, drop into another site (refused), area into its own child (refused), mouse drag with drop indicators, Edit → Inside. 45 unit tests pass (new: `test_move_and_nest`).
