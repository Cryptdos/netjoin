# NetJoin v0.10 – devices in the tree and device pages

Branch: `v0.10` (built on `v0.9.1`). Status: built, tested in demo mode and against a simulated BACnet device. Plan: [device-tools-plan.md](device-tools-plan.md).

NetJoin reads, observes and connects – nothing on this page writes to a device.

## Devices in the Sites list

- Every network can be opened (▸) to show its devices. BACnet devices first, by name, with their instance (`RA L2-01  #2502`); then other devices by IP.
- Dot: green = answered the latest scan, amber + struck through = missing, grey = on an imported list but not checked yet.
- Devices load when a network is opened in the list (from what NetJoin already knows – nothing is scanned).
- The Sites search box finds devices too: IP, name, MAC, model or instance number (2+ characters). Matching devices show under their networks.
- In a network's device list, the **IP is a link** to the device page.

## Device page

`Home › 50 Berkeley Street › Level 2 › FCUs › RA L2-01`

- **Top bar:** Web UI ↗ (when port 80 / 443 / 8080 is open), Ping, and Revert to DHCP as usual.
- **Facts strip:** IP (and the router it's behind, for MS/TP devices), MAC (+ NIC maker), BACnet instance (+ vendor), model, status.

| Tab | What's in it |
|---|---|
| Overview | Status, which scans found it, response time, first / last seen, network link(s), firmware (once read), on the imported list, other addresses the same MAC has been seen at, **Notes** (one free-text field, like a network's) |
| Ping | **Live ping** – once a second: now replying / not replying, last, min / avg / max, sent, lost %, a 2-minute bar chart (red = no reply), and a list of drop-outs ("Stopped replying 13:42:10", "Replying again – down 21 s"). Optional beep on drop-out (low) and recovery (high) |
| BACnet | **Device properties**, read when the tab opens: name, vendor, model, firmware, application software version, protocol version / revision, location, description, system status, max APDU, segmentation, database revision, device date / time, UTC offset, serial number (if it has one). **Clock check**: warns when the device clock is more than 2 minutes off the laptop's |
| Ports | Open BMS ports with links (web pages), `ssh` / `telnet` commands to copy, Fox / Modbus addresses; **Check ports now** re-checks this device |

### Live ping and battery

The ping runs only while that device's page is open. It stops when you leave the page, after 20 s with the window hidden / minimised, or after an hour. Switching tabs on the device page keeps it going (a pulsing dot on the Ping tab).

### BACnet reads

- Done with NetJoin's own BACnet client: one ReadPropertyMultiple for all the properties, or one ReadProperty each if the device doesn't do RPM. Devices behind a BACnet router (MS/TP) are reached through the router.
- Firmware and application version are remembered for the v0.11 health checks; a blank name / model / vendor is filled in.
- Needs the laptop on the device's subnet (the tab says so, with a link to Join).

## Back end

- `netjoin/scan/bacnet_client.py` – ReadProperty, ReadPropertyMultiple, Who-Has, value decoding (all BACnet application types), errors / rejects / aborts, routed devices, no segmented replies (falls back to smaller reads). Read-only by design.
- `netjoin/scan/devtools.py` – live ping sessions, BACnet device properties with clock check, single-device port check.
- API: `GET /api/device/{id}?network_id=`, `PUT /api/device/{id}/notes`, `POST /api/device/{id}/bacnet`, `POST /api/device/{id}/ports`, `GET /api/devices/search?q=`, `POST /api/ping`, `GET /api/ping/{sid}?after=`, `POST /api/ping/{sid}/stop`.
- Devices table: `notes`, `firmware`, `app_version`, `props_ts` (carried by site export / import).

## Tests
