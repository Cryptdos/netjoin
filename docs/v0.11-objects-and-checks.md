# NetJoin v0.11 – object list, checks and Find point

Branch: `v0.11` (built on `v0.10`). Status: built, tested in demo mode and against a simulated BACnet device. Plan: [device-tools-plan.md](device-tools-plan.md). Everything here only reads.

## Objects tab (BACnet device pages)

**Read object list** reads every object in the controller: name, description, present value with units, status flags, priority array and relinquish default. A room controller takes a second or two; a big automation station can take a minute (progress bar, **Cancel** keeps what was read so far).

| Tool | What it does |
|---|---|
| Search | Name, description, `AV 3` / `AV3`, object type or value |
| Types ▾ | Tick-list of the object types in this device, with counts (AI, AO, AV, BI, BO, BV, MSV, SCH, TL, …) |
| Chips | **All**, **Commanded** (something in the priority array), **Overridden** (status flag – a local override such as a hand switch), **Out of service**, **In alarm**, **Fault** (fault flag or a reliability problem). Each shows its count; empty ones are hidden |
| Columns | Object, Name, Description, Value + units, Flags, Priority – the highest active priority (`@8 23.5`, amber when 1–8, i.e. manual), "+2 more"; hover for the whole array and the relinquish default |
| Sort | Object (type then number), Name or Value |
| Refresh values | Re-reads present value, flags and priority array of the objects shown (up to 400) – quick |
| Auto-refresh (10 s) | Off by default; only while this tab is open and the window is visible |
| Export CSV | The objects shown, filters applied |
| Read again | The whole list again |

Multi-state values show their state text (e.g. *Comfort*, *Stage 2*), binary values their active / inactive text (*On* / *Off*). The list stays in memory while NetJoin runs, so going back to the tab is instant.

## Checks (site, area and network pages)

A **Checks** button next to Scan, with the number of findings (amber when any are warnings). It looks at what NetJoin already knows – no network traffic – except **Read firmware now**, which reads the firmware of every BACnet device on the subnet the laptop is on.

| Check | Severity |
|---|---|
| The same BACnet instance on two or more devices (across the whole site) | warning |
| Instance 4194303 – the "not configured" number | warning |
| An address answering with a different MAC than before (two devices on one IP, or a swapped unit) | warning |
| A device answering on this cable from an address outside the subnet (factory-default IP, wrong settings) | warning |
| One MAC at several addresses on the same subnet | info |
| Firmware that differs between devices of the same model | info |

Each finding lists the devices, linked to their device pages.

## Find point (network pages)

**Find point** asks every controller on the laptop's subnet – including MS/TP devices behind routers – which one holds an object with an exact name (BACnet Who-Has). Results: device (linked), object (`AV 1`), name.

## Back end

- `bacnet_client.read_object_list` / `read_objects` (RPM in batches; smaller batches when a reply is too big; ReadProperty when RPM isn't supported; element-by-element object-list when the whole list won't fit) and `who_has`.
- `devtools`: object-list jobs with progress / cancel, value refresh, firmware job, Who-Has.
- `store.health()`; devices remember `prev_mac` / `mac_changed` when an address answers with a new MAC.
- API: `POST/GET /api/device/{id}/objects`, `POST /api/device/{id}/objects/refresh`, `GET /api/jobs/{id}`, `POST /api/jobs/{id}/cancel`, `GET /api/health?node_id=`, `POST /api/health/firmware?node_id=`, `POST /api/who-has`.
